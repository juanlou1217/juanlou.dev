# Polish Checklist

Use this file only when you need a second-pass editing checklist for a technical blog post.

## Angle

- Is there one main point
- Can the article be summarized in one sentence
- Does every major section support that point

## Reader fit

- Is the target reader obvious
- If the piece is for beginners, are assumptions explained early
- If commands are included, are prerequisites stated

## Structure

- Does the opening explain why the topic matters
- Are sections ordered from motivation to execution to reflection
- Are there any sections that repeat earlier ideas
- For personal reflection posts, is there a visible main route such as self -> environment -> action
- Are heading levels doing different jobs, instead of every heading sounding like a climax
- Does the article preserve the user's hierarchy of importance, instead of giving every minor idea equal weight

## Language

- Replace vague claims with concrete statements
- Replace generic praise with specific tradeoffs
- Cut filler transitions
- Break long paragraphs that carry more than one idea
- For spoken-note drafts, preserve vivid original-feeling lines and emotional peaks
- Do not polish away the author's hesitation, excitement, embarrassment, or sudden insight when it carries the voice
- If a paragraph feels like a formal report, add back concrete scenes, names, reactions, or first-person texture from the source notes

## Repo accuracy

- Check file paths
- Check route names
- Check command names
- Check feature status against current docs and code

## Tone

- Practical, not grandiose
- Warm but not sentimental
- Confident but not performative
- Helpful to new AI users without overselling AI
- For personal posts, structured but alive
- Keep the author's personal rhythm and emotional color; do not flatten it into a generic essay
